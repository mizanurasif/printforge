# PrintForge

A full-stack marketplace for 3D-printable models. Browse a catalog of designs, spin them around in an interactive **3D viewer**, like your favorites, follow creators, upload your own models, or **turn a 2D picture into a 3D model with AI**.

Built with **Next.js 16 (App Router)**, **TypeScript**, **PostgreSQL**, **NextAuth**, **three.js** and **Tailwind CSS**, with image-to-3D generation by **Hunyuan3D-2** on Hugging Face.

---

## Features

### Interactive 3D viewer
- Every catalog model has a real `.glb` file you can **rotate, pan and zoom** on its detail page
- Animated 3D phoenix in the home page hero
- Built directly on **three.js** (WebGL renderer, `GLTFLoader`, `OrbitControls`, studio lighting from `RoomEnvironment`)
- Auto-framing: each model is centered and the camera is pulled back until it fits, whatever its size or units
- **Code-split and client-only**: three.js loads in its own chunk through `next/dynamic` (`ssr: false`), so pages that don't show a model never download it
- A loading spinner while the 3D file downloads, and an error state if it fails
- Light sky-blue background behind every model and picture, so white models (like the AI-generated ones) stand out
- **Download** button on the model page that saves the `.glb` under the model's name
- Full cleanup on unmount (geometries, materials, textures, WebGL context) so navigating between models doesn't leak GPU memory
- Touch-friendly: when zoom is off, vertical swipes still scroll the page

### 2D to 3D: AI model generation (`/generate`)
- Upload a picture of an object and get a **3D model (`.glb`) back in about 30–60 seconds**, generated by Tencent's [Hunyuan3D-2](https://huggingface.co/spaces/tencent/Hunyuan3D-2) on Hugging Face's free ZeroGPU hardware
- Flow: pick a picture → loading screen with a live seconds counter → **3D preview** of the result → "Generate again", or save it with a name, description and category
- Login required: the navbar link sends logged-out users to the login page and back again
- **Talks to the model's Gradio API directly with `fetch`** (no SDK): uploads the image, queues the job, reads the result from the Server-Sent Events stream, and downloads the mesh. All of it runs on the server, so the browser never talks to Hugging Face
- Defensive: a 5-minute timeout, the downloaded file is checked for a real glTF header and the 50MB limit, and every failure (Space busy, GPU quota used up, unusable picture) becomes a clear message for the user
- **One generation at a time per user**, because every request uses the same shared free GPU quota
- Nothing is stored until the user decides to keep the model. **Saving is one atomic request** (`POST /api/models`): the picture and `.glb` are saved first and the database row is inserted last, and anything already saved is removed if a later step fails. An interrupted save (reload, closed tab, lost connection) can't leave a model without its 3D file
- A snapshot of the 3D preview becomes the model's catalog picture
- Optional `HF_TOKEN` raises the daily GPU quota (see [Environment variables](#3-environment-variables))

### Catalog
- 47 models across 11 categories, each showing its creator
- **Search** by name or description (case-insensitive)
- **Sort** by most popular, A–Z, or most recent
- **Filter** by category
- **Server-side pagination**: only the current page is fetched from the database
- Model detail pages with creator, category, likes, upload date and a `.glb` download
- Loading states and custom 404 pages

### Authentication
- Register and log in with email + password (NextAuth Credentials provider)
- Passwords hashed with **bcrypt**; the plain password is never stored
- Encrypted JWT session cookie (HttpOnly)
- Same error for "unknown email" and "wrong password", so accounts can't be discovered through the login form
- Private routes protected by **Next.js Proxy** (`proxy.ts`), with a redirect back to the requested page after login
- Open-redirect protection on the `callbackUrl` parameter

### Upload, edit and delete your models
- Upload page with an image picker, preview, and a live preview card that updates as you type
- Images up to 5MB (PNG, JPG or WebP), processed with **sharp**: auto-rotated from EXIF data, cropped to 500×500 and converted to WebP under a random file name. Without an image, a placeholder is used
- Server-side validation with **zod**: field lengths, the category must exist in the database, image type and size. The rules live in one shared module used by upload, edit and AI generation
- **3D model upload**, required for every model (`.glb`, up to 50MB):
  - **Live 3D preview** in the form before anything is uploaded (the file is shown from a local `blob:` URL)
  - Without an image, a **snapshot of the 3D preview** becomes the catalog picture
  - Sent to its own Route Handler (`PUT /api/models/[id]/file`) with a progress bar, because Server Actions are capped at 6MB. The body **streams to disk** instead of being held in memory
  - The server checks the binary glTF header and the real byte count, not the file name or `Content-Length`, and deletes partial files on failure
  - If the file upload fails, the just-created model is deleted again, so no model exists without its 3D file
  - Saved as `public/models/<category>/upload-<uuid>.glb`, moved if the category changes, and replaceable from the edit page
- **Edit** and **delete** your own models from the dashboard; deleting a model also removes its uploaded image and 3D file
- **Ownership checks on the server**: updates and deletes only touch rows where `user_id` matches the logged-in user, so nobody can change someone else's model by guessing an id
- Login is checked inside every Server Action, not only on the page

### Likes
- Like and unlike models; the heart and count update instantly (optimistic update with `useTransition`), roll back if the request fails, then sync to the real count from the database
- One like per user per model, enforced by the database (composite primary key on `likes`)
- The count on each model is updated in the same transaction as the `likes` row, with the model row locked, so two likes at the same moment can't miscount

### Creator profiles (`/user/[id]`)
- Public page with the creator's name, join date, number of models and likes received
- Their models, most liked first, with **server-side pagination** (only the current page is fetched; the stats are counted over all their models)
- Creator names on model cards and detail pages link to their profile

### Dashboard (`/dashboard`)
- Stats: models uploaded, total likes received (with the average per model), most-liked model
- "My models" table with a sticky header and scrolling; turns into a compact list on mobile
- View, edit and delete actions on every row
- **Delete account**, confirmed with your password, which also removes your uploaded images
- Empty state for users without uploads

### Database
- **PostgreSQL** with a relational schema: `users`, `categories`, `models` (`models.user_id → users.id`) and `likes` (many-to-many between users and models)
- Parameterized queries with [postgres.js](https://github.com/porsager/postgres); sort options come from a whitelist, so user input never becomes SQL
- Versioned **migrations** (node-pg-migrate, plain SQL with up and down steps), hosted on **Neon** serverless Postgres
- Seed script that runs in a single transaction, creates demo creators and assigns every model to one of them

## Getting started

### Prerequisites
- Node.js 20.11 or newer
- A PostgreSQL database: local (with pgAdmin 4, or `psql`) or a free one on [Neon](https://neon.tech)

### 1. Install dependencies
```bash
npm install
```

### 2. Create the database
Either a local one (in pgAdmin create a database called `printforge`) or a free hosted one on [Neon](https://neon.tech). You only need its connection string for the next step: the tables are created by the migrations in step 4.

### 3. Environment variables
Create a `.env` file in the project root:

```env
DATABASE_URL=postgresql://postgres:YOUR_PASSWORD@localhost:5432/printforge
NEXTAUTH_SECRET=generate-one-with-npx-auth-secret
NEXTAUTH_URL=http://localhost:3000
```

If your database password has special characters, URL-encode them (`@` → `%40`, `#` → `%23`).

For **Neon**, use the connection string from its dashboard:

```env
DATABASE_URL=postgresql://USER:PASSWORD@ep-xxx.region.aws.neon.tech/neondb?sslmode=require
```

Neon shows two strings: **direct** and **pooled** (its host contains `-pooler`). Use the direct one for migrations. For a deployed app, the pooled one handles many connections better.

**Optional, for 2D to 3D:** add a free Hugging Face token (Settings → Access Tokens, type *Read*):

```env
HF_TOKEN=hf_xxxxxxxxxxxxxxxx
```

Generation works without it, but the GPU quota is per caller, and all users of your server share one. Hugging Face's ZeroGPU daily quota is 2 minutes of GPU time without a token and 5 minutes with a free account (40 with PRO), which is very roughly 5–15 and 15–35 generations a day. It resets 24 hours after first use.

### 4. Create the tables, seed and run
```bash
npm run db:migrate   # creates the tables (runs every migration not yet applied)
npm run db:seed      # 3 demo users, 11 categories, 47 models
npm run dev
```

Open [http://localhost:3000](http://localhost:3000).

### Changing the schema
The schema is built by **migrations** ([node-pg-migrate](https://github.com/salsita/node-pg-migrate)), plain SQL files in `migrations/`. Each one runs once per database, and the `pgmigrations` table records which have run, so the same files keep a local database and Neon in sync.

```bash
npm run db:migrate:create add-something   # new file in migrations/, write the SQL under "-- Up Migration" and "-- Down Migration"
npm run db:migrate                        # apply it to the database in DATABASE_URL
npm run db:migrate:down                   # undo the last one
```

**Moving an existing database** (for example local → Neon): run `npm run db:migrate` against the new database to create the tables, then copy the rows:

```bash
pg_dump --data-only --no-owner --no-acl -T 'pgmigrations*' "<old database url>" > data.sql
psql "<new database url>" -f data.sql
```

## Project structure

```
app/
├── 3d-models/            # Catalog, category pages, model detail page
├── user/[id]/            # Public creator profiles
├── dashboard/            # Dashboard, upload and edit pages (protected)
├── generate/             # 2D to 3D page (protected)
├── login/ register/      # Auth pages
├── about/
├── api/auth/[...nextauth]/route.ts
├── api/generate/route.ts           # Picture in, generated .glb out (nothing saved)
├── api/models/route.ts             # Creates a model with its picture and .glb in one request
├── api/models/[id]/file/route.ts   # Streams an uploaded .glb to disk
├── components/
│   ├── Model/            # Cards, grid, like button, ModelPreview + ModelViewer (three.js)
│   ├── HeroModel.tsx     # Animated home page model
│   ├── generate/         # The 2D to 3D form (pick, generate, preview, save)
│   └── dashboard/        # Dashboard-only components
├── data/                 # Seed data (models and categories)
└── lib/
    ├── auth.ts           # NextAuth options
    ├── hunyuan.ts        # Hunyuan3D-2 client (Gradio HTTP API)
    ├── imageUtils.ts     # Save / delete uploaded images (sharp)
    ├── modelFileUtils.ts # Save (with glTF checks) / move / delete uploaded .glb files
    ├── modelValidation.ts # Shared zod rules for a model's details and picture
    ├── models.ts         # Shared types
    └── database/         # db.ts (connection), model, category, user and like queries
public/
├── models/               # .glb files, one folder per category (credits in SOURCES.md)
└── img/thumbnails/       # Catalog thumbnails
scripts/
└── seed.ts               # Demo data
migrations/               # Schema changes, oldest first (node-pg-migrate)
proxy.ts                  # Route protection
```
